## Quick start

```sh
python3 tests/fixtures/generate.py            # ~6 s the first time, instant when up to date
node tests/e2e/smoke-mock.mjs                 # mock API contract (exit code 0 = pass)
node tests/e2e/smoke-browser.mjs              # same, from Chromium via Playwright

# manual testing: app on :8080, mock Drive on :8787, prints a ready-to-open URL
node tests/e2e/harness.mjs --app-port 8080 --drive-port 8787 [--max-page-size 4] [--verbose]
# → http://127.0.0.1:8080/?apiBase=http%3A%2F%2F127.0.0.1%3A8787&folder=folder_root&key=TESTKEY
```

The app honours `?apiBase=` only when it is opened on localhost/127.0.0.1 and the target is
local (see `resolveApiBase` in `js/settings.js`). Alternatively `routeGoogleApis()` (below)
redirects the real `https://www.googleapis.com/drive/...` URLs to the mock inside Playwright.

**Content-Security-Policy.** `index.html` carries the production CSP in a `<meta>` (only the app's own
origin and the Google endpoints; no localhost). The test static server (`startStaticServer`) and the dev
server (`npm start`, `scripts/serve.mjs`) serve HTML with that policy extended — `connect-src`, `img-src`,
`media-src` only — by the loopback origins of the mock (`cspOrigins`) and of the page's own `?apiBase=`
(`scripts/dev-csp.mjs`; non-loopback origins are never added). So the whole suite runs under the real CSP:
no `eval` / `new Function` / inline scripts or `style` attributes in the page (Playwright's *string*
`waitForFunction` / `evaluate` forms use `eval` and fail; pass functions).

Requirements: Python 3.9+ with Pillow and `pillow_heif`; `ffmpeg`/`ffprobe` with libx264,
libx265 and the native AAC encoder; Node 22; Playwright (for the browser smoke test / E2E).
No npm dependencies are needed — the harness loads a globally installed `playwright` through
`createRequire` / `NODE_PATH`.

## 1. Fixtures (`tests/fixtures/generate.py`)

```
python3 tests/fixtures/generate.py [--out tests/fixtures/out] [--force] [--clean]
```

* **Idempotent.** Every output is keyed by a hash of its spec *and of the script itself*; unchanged
  outputs are skipped (`.cache.json`). `--force` re-encodes everything, `--clean` deletes the
  output directory first. Encoding is deterministic (x264 single-threaded), so a forced rebuild
  produces byte-identical files and the same `manifest.json`.
* **Self-verifying.** Before writing `manifest.json` the script re-derives every expected time from
  the generated bytes with independent parsers (its own EXIF reader over the first 64 KiB, its own
  MP4/QuickTime box parser for `mvhd` and `moov/meta` mdta keys), cross-checks them with Pillow and
  `ffprobe`, and asserts the oracle properties listed under *Oracles*. Any mismatch aborts.

Output layout (`--out`, default `tests/fixtures/out`):

| path | content |
|---|---|
| `files/<parentFolderId>/<name>` | media/binary files served by the mock (`_test.path`) |
| `thumbs/<id>_s220.jpg`, `thumbs/<id>_s1024.jpg` | upright JPEG thumbnails (`_test.thumbs`) |
| `manifest.json` | Drive v3 File resources + `_test` oracle data |

### The trip

A fictional four-day trip, 2025-07-12 … 2025-07-15, trip time zone `Europe/Athens` (UTC+3 in summer,
UTC+2 in winter, EU DST rules). `TRIP_TZ` in `e2e/lib.mjs` (`openSuite()` checks it against
`manifest.tripTimeZone`) is seeded as the `timeZone` setting, while every browser context runs in
`DEVICE_TZ` = `America/Los_Angeles` (10 h behind in July: most fixtures fall on another calendar day there), so
code that formats or groups times in the device's zone instead of the trip zone setting fails the caption and
day-card checks. The app's default trip zone is the device's zone; the tests of that default compare with the
page's own zone or pass `contextOptions: { timezoneId }`.
Every image is ~1280×853 (screenshot 720×1280, `folder_big` 64×48) and shows, in large text, its
label with the **true local capture time** (e.g. `Day1 12:05 City square`) and its id, on a
distinct solid background colour. The outer 10 % of every image / video frame is pure background
colour (`_test.bgColor`), so a test can sample a pixel near a corner of the displayed slide and map
it back to an id (H.264 shifts colours by a few units; use a tolerance of ~24).

Videos are 640×360, 30 fps, H.264 High (CBR 1.2 Mbit/s, so `moov` at the end lies far beyond the
first 256 KiB) + silent AAC stereo, a static label card with a small moving square.

### App time rules (the oracle)

Trip time zone (setting `timeZone`, `Europe/Athens` in the tests; the app's default is the device's zone):

1. image with Drive `imageMediaMetadata.time` → that wall clock (`YYYY:MM:DD HH:MM:SS`) in the trip zone;
2. JPEG without Drive time → read EXIF from the first bytes (Range request): `DateTimeOriginal`,
   with `OffsetTimeOriginal` if present, else the trip zone;
3. video → MP4/MOV `com.apple.quicktime.creationdate` (ISO with offset) if present, else `mvhd`
   creation_time if after year 2000 (UTC);
4. filename: `PXL_YYYYMMDD_HHMMSSmmm` = UTC; `IMG_/VID_/PANO_/Screenshot_` + `YYYYMMDD[_-]HHMMSS`,
   `YYYYMMDD_HHMMSS`, `YYYY-MM-DD HH.MM.SS` = trip zone;
5. else `min(modifiedTime, createdTime)`.

Per-camera offsets (setting `cameraOffsets`, stored per folder id: `{ [folderId]: { [group]: minutes } }`, and
carried in share links as repeated `fix=<minutes>:<group>`) are added to the times of that correction group.
A time read with an explicit UTC offset that differs from the trip zone's offset at that instant (EXIF
`OffsetTime*`, Apple `creationdate` / `©day` with an offset) or from a `PXL_` filename (UTC) belongs to a
separate group `<camera>（タイムゾーン記録あり）`, so an offset saved for the plain camera group (wall clock read
in the trip zone) never applies to it twice. When the recorded offset equals the trip zone's, both readings give
the same time and the item stays in the plain group (a clock-drift correction keeps applying after refine).
A video with a camera label whose time comes from `mvhd` (read as UTC; many cameras write local time there)
gets its own group `<camera>（動画）`, corrected apart from that camera's photos. Corrections saved by an older
version as a flat `{ group: minutes }` map are migrated to the folder saved with them.

### Endpoints

| method | path | |
|---|---|---|
| GET/HEAD | `/drive/v3/files?q&fields&pageSize&pageToken&orderBy&supportsAllDrives&includeItemsFromAllDrives&key` | files.list |
| GET/HEAD | `/drive/v3/files/{id}?fields&supportsAllDrives&key` | files.get (metadata) |
| GET/HEAD | `/drive/v3/files/{id}?alt=media[&key]` (+ `Range`) | download |
| GET/HEAD | `/thumb/{id}=s{N}` or `=w{W}-h{H}` | thumbnail JPEG (`thumbnailLink`) |
| OPTIONS | any | CORS preflight |
| * | `/__admin/...` | test control (no auth) |

Unknown query parameters (`supportsAllDrives`, `includeItemsFromAllDrives`, `corpora`, …) are ignored.

**Auth.** `Authorization: Bearer <token>` (or `?access_token=`) with an allowed token → OAuth mode,
all items visible. Otherwise `?key=<key>` with an allowed key → API-key mode: only items whose
fixture is public; items with a `resourceKey` additionally need `X-Goog-Drive-Resource-Keys:
<id>/<key>[,<id>/<key>…]` containing **their own** id/key (for `files.list`, the listed folder's key;
children of a folder opened with its key are listed, but downloading/getting them needs their own key).
A bearer header takes precedence over `key`. Errors (Google JSON):

| case | status | `error.errors[0].reason` | `error.status` |
|---|---|---|---|
| invalid/expired bearer (+ `WWW-Authenticate: Bearer realm="https://accounts.google.com/", error="invalid_token"`) | 401 | `authError` (message `Invalid Credentials`, location `Authorization`/header) | `UNAUTHENTICATED` |
| no credentials | 403 | `dailyLimitExceededUnreg` (domain `usageLimits`) | `PERMISSION_DENIED` |
| invalid API key | 400 | `badRequest` + `details[0].reason = API_KEY_INVALID` | `INVALID_ARGUMENT` |
| unknown / not accessible / hidden / missing resource key | 404 | `notFound`, message `File not found: <id>.`, location `fileId` | — |
| bad `q`, `pageSize` (∉ 1..1000), `pageToken`, `orderBy`, `alt` | 400 | `invalid`, location = the parameter, message `Invalid Value` for `q`/`pageToken` | — |
| bad `fields` | 400 | `invalidParameter`, message `Invalid field selection <x>` | — |
| `alt=media` on folder / Google Doc / shortcut | 403 | `fileNotDownloadable` | — |
| unsatisfiable Range (+ `Content-Range: bytes */<size>`) | 416 | `requestedRangeNotSatisfiable` | — |

**files.list.** `q` supports `'<id>' in parents` (`'root'` = My Drive), `name` / `mimeType` with
`=`, `!=`, `contains` (case-insensitive substring), `trashed` / `starred` `= true|false` (also
`trashed=false`), `createdTime` / `modifiedTime` with `= != < <= > >=` and RFC 3339 values, combined
with `and`, `or`, `not` and parentheses; `\'` escapes. Anything else → 400. Trashed items **are**
returned unless the query says `trashed = false`. Results are ordered by name (code-point order,
tie → id), **not** chronologically; `orderBy` supports `name, name_natural, createdTime, modifiedTime,
recency, folder, quotaBytesUsed, starred` (+ `desc`, comma-separated; other valid Drive keys are
accepted and ignored). `pageSize` default 100, max 1000, further capped by `--max-page-size`.
`nextPageToken` is returned while more results exist (only if selected by `fields`); a token is
bound to the same `q`/`orderBy`/auth mode.

**fields (partial response).** Real semantics: `nextPageToken,files(id,name,imageMediaMetadata(time,cameraModel))`,
slash paths (`files/id`, `imageMediaMetadata/location/latitude`), `*` and `files(*)`; unknown field
names (validated against the Drive v3 File schema incl. nested `imageMediaMetadata`,
`videoMediaMetadata`, `shortcutDetails`) → 400. Absent fields are omitted, empty nested objects are
dropped. Defaults: list → `kind, nextPageToken, incompleteSearch, files(kind,id,name,mimeType)`;
get → `kind,id,name,mimeType`.

**Media.** `Content-Type` = the file's mimeType, `Accept-Ranges: bytes`, `Content-Length`,
`X-Goog-Hash: md5=…`, `Last-Modified`. `Range: bytes=a-b | a- | -n` → 206 + `Content-Range`;
start ≥ size → 416; malformed / multi-range → 200 with the full body. HEAD returns the same headers.

**Thumbnails.** `thumbnailLink` = `http://<host:port>/thumb/<id>=s220` (built from the request's
`Host` header). `N ≤ 220` → the 220 px variant, otherwise the 1024 px one; upright (EXIF orientation
applied), also for HEIC and videos. No auth by default; hidden/unknown ids → 404.

**CORS.** Preflight: `200`, `Access-Control-Allow-Origin: <Origin>`, `-Allow-Methods: GET,HEAD,OPTIONS`
(`+POST` for `/__admin`), `-Allow-Headers: <Access-Control-Request-Headers>`, `-Max-Age: 3600`.
Every response to a request with `Origin` echoes it in `Access-Control-Allow-Origin` and lists **all**
response header names in `Access-Control-Expose-Headers` (like googleapis.com). Thumbnails use
`*` when there is no Origin.

### Admin API (no auth, CORS enabled, JSON responses `{ok:true,…}`)

| request | effect |
|---|---|
| `POST /__admin/reveal?id=ID` | make a `hiddenUntilRevealed` item visible (404 for unknown ids) |
| `POST /__admin/reveal-all` | reveal all hidden items → `{ids}` |
| `POST /__admin/hide?id=ID` | hide an item again |
| `POST /__admin/trash?id=ID`, `/untrash?id=ID` | toggle `trashed` |
| `POST /__admin/delete?id=ID` | remove an item (until reset) |
| `POST /__admin/tokens` `{"tokens":["t1"]}` | replace allowed bearer tokens (GET shows them) |
| `POST /__admin/keys` `{"keys":["K"]}` | replace allowed API keys |
| `POST /__admin/latency?ms=N` | artificial latency for every non-admin request (incl. preflights, thumbnails) |
| `POST /__admin/fail?id=ID&status=500&times=1` | next N `alt=media` requests for ID fail (`times=0` clears) |
| `POST /__admin/reset` | restore the initial state (tokens, keys, hidden, trash, latency, fails, log) |
| `GET /__admin/log` | array of `{method, path, query, range, auth: 'bearer'\|'key'\|'none', authOk, status, ts, durationMs, resourceKeys, origin}` (admin calls excluded, OPTIONS included; `auth` = credential type presented) |
| `POST /__admin/log/clear` | clear the log |
| `GET /__admin/state`, `GET /__admin/manifest`, `GET /__admin/health` | introspection |

`startMockDrive()` / `startServers()` also return `admin` (`adminClient(url)`): `reveal(id)`,
`revealAll()`, `hide(id)`, `trash(id)`, `untrash(id)`, `remove(id)`, `setTokens([])`, `setKeys([])`,
`reset()`, `log()`, `clearLog()`, `setLatency(ms)`, `fail(id, status, times)`, `state()`, `manifest()`.

## 3. E2E harness (`tests/e2e/harness.mjs`)

```js
import { startServers, loadPlaywright, routeGoogleApis, expectedOrder, filesById, TEST_KEY, TEST_TOKEN } from './harness.mjs';

const env = await startServers({ appPort: 0, drivePort: 0, maxPageSize: 4 /*, driveOptions: { latencyMs, thumbAuth, … } */ });
// env.appUrl, env.driveUrl, env.admin, env.manifest, env.app, env.drive
const { chromium } = loadPlaywright();
const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto(env.appUrlFor({ folder: 'folder_root', key: TEST_KEY }));   // ?apiBase=<mock>&folder=…&key=…
// … assert slide order against expectedOrder(env.manifest, 'default', { skipOptional: true })
await browser.close(); await env.close();
```

* `startServers({appPort, drivePort, host, appRoot, fixturesDir, maxPageSize, driveOptions})` →
  `{appUrl, driveUrl, admin, manifest, app, drive, appUrlFor(params), close()}`. Generates the
  fixtures first if `manifest.json` is missing. The static server serves the repository root with
  `Cache-Control: no-store`, `index.html` for directories (301 to the trailing-slash URL first),
  `text/javascript` for `.js/.mjs`, `application/wasm`, `image/heic`, etc.
* `startStaticServer({root, port, host, cspOrigins})` (`cspOrigins()` → extra loopback origins for the CSP of
  served HTML; `startServers` passes the mock's URL), `ensureFixtures({force})`, `loadManifest()`.
* `routeGoogleApis(pageOrContext, driveUrl)` — Playwright route that forwards
  `https://www.googleapis.com/drive/**` (and `content.googleapis.com`) to the mock, for testing the
  app with its default API base. OAuth itself (Google Identity Services) is not mocked: inject a
  token the way the app allows (the mock accepts `test-token`).
* `expectedOrder(manifest, 'default'|'reveal'|'canonFix'|'true', {skipOptional})`, `filesById(manifest)`.
* `package.json` runs `tests/e2e/**/*.test.mjs` with `node --test --test-concurrency=1`; the
  smoke scripts are deliberately not named `*.test.mjs`.

### Browser notes (Playwright Chromium 158, Linux)

* H.264/AAC in `.mp4` and in the QuickTime `.mov` play (although `canPlayType('video/quicktime')`
  is `""`), also with `moov` at the end.
* **HEVC** (`vid_hevc`): `canPlayType` is `""`, but `<video>` still fires `loadeddata` and plays the
  AAC track while `videoWidth/videoHeight` stay `0` — no `error` event. Detect it via
  `videoWidth === 0`. The manifest marks it `optional`.
* **HEIC** is not decodable by `<img>`; the thumbnail is.
* EXIF orientation is applied by `<img>`/`createImageBitmap` (cathedral shows as 853×1280).

`node tests/e2e/smoke-browser.mjs` verifies all of the above plus CORS from a real page origin.

## 4. E2E suite (`tests/e2e/*.test.mjs`)

```sh
npm run test:e2e                        # = node --test --test-concurrency=1 "tests/e2e/**/*.test.mjs"  (~6 min)
node --test tests/e2e/05-oauth.test.mjs # one file
node --test --test-name-pattern="^9b" tests/e2e/05-oauth.test.mjs   # one test
```

Each file starts its own app server + mock Drive on ephemeral ports (`openSuite()` in `lib.mjs`)
and its own headless Chromium; every test opens a fresh browser context (fresh storage and
Service Worker registration). On failure every open page is saved as
`tests/e2e/out/FAIL-<test>-<n>.png`; some tests also save reference screenshots there
(`mobile-*.png`, `orientation-cathedral.png`, `heic-slide.png`). No npm dependencies: Playwright
is loaded from the global install (`loadPlaywright()`).

### How the tests observe the app

* `window.__slideshow` (the app state, exposed on localhost): `items`, `player.slides/index/playing/videoPreload`,
  `settings`, `sw`, `loader`, `session`.
* An init script (`RECORDER` in `lib.mjs`) records, in page order, every slide that becomes
  `#player .slide.visible` (`window.__slideLog`: kind, id, day, caption text, `<img>` natural size,
  src and the colour of a pixel near the photo's corner — compared with the fixture's `bgColor` to
  prove the *right* picture is on screen), every toast (`window.__toasts`), the progress of every
  `<video>` (`window.__video[id]`: max `currentTime`, `videoWidth`, `src`, `muted`) and every
  `securitypolicyviolation` (`window.__csp`). `cspViolations(app)` / `assertNoCspViolations(app)` combine
  those with the CSP console messages of the whole context; the full playthrough and the main scenarios
  (02 › 2, 2c, 10a, 10b · 03 › 4 · 05 › 9a, 9c, 9d · 06 › 11, 11b · 09 › 20 · 11 › S1, S4, S4b) assert none.
* `app.waitForLog(pred)` waits until `pred(window.__slideLog)` is true (`pred` runs in the page and must be a
  function, not source text — see the CSP note above).
* The mock's request log (`admin.log()`): auth type, Range, resource-key header, origin (requests
  with the app origin and `mode: cors` come from the Service Worker), status.
* Settings are seeded into `localStorage` (`SETTINGS_KEY` = `photo-slideshow.settings.v1`) before the first
  load (`FAST_SETTINGS`: 1 s photos, 2 s videos, no auto refresh, trip zone `TRIP_TZ`) unless a test passes
  `settings: null`; URL parameters still win. Browser contexts run in `DEVICE_TZ` (`America/Los_Angeles`)
  unless a test passes `contextOptions: { timezoneId }`; with `settings: null` the trip zone defaults to it.
* Google Identity Services is replaced by `GIS_STUB` (route on `accounts.google.com/gsi/client`):
  `window.__nextToken`, `__nextExpiresIn`, `__nextTokenError` steer the next token response and
  `window.__gis.requests` counts token requests, `window.__gis.clientId` is the client ID it was initialised
  with and `window.__gis.revoked` lists revoked tokens. `https://drive.google.com/**` (the `/preview`
  iframe) is answered with a stub page and recorded (`app.previewRequests`). A test can serve a deployment
  `config.js` with `context.route()` (11-security `withDeployConfig`).
