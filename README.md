# 旅の写真スライドショー

Google ドライブのフォルダに入れた写真・動画を、**撮影した順に並べてスライドショーで再生する**ウェブアプリです。
旅行やイベントで、複数のスマートフォンやカメラで撮った写真・動画が混ざっていても、ファイルに記録された撮影日時を読み取って時系列に並べます。

- サーバー不要の静的サイトです（HTML / CSS / JavaScript のみ、ビルド不要）。GitHub Pages にそのまま公開できます。
- 写真・動画はブラウザと Google の間だけでやり取りされ、ほかのサーバーには送られません。
- 再生中にフォルダへ追加した写真・動画も、自動更新で撮影日時の位置に入ります。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 時系列の並び替え | 写真は EXIF の撮影日時（時差の記録があればそれも使用）、動画はファイル内のメタデータ（iPhone の撮影日時、MP4 の作成日時など）で並べます。見つからなければファイル名の日時（`IMG_20250712_143000.jpg`、`PXL_…` など）、最後の手段としてドライブ上の日時を使います。詳しくは「[並び順の決め方](#並び順の決め方)」。 |
| 撮影地のタイムゾーン | 時差の記録がない撮影日時は、撮影地のタイムゾーンの現地時刻として扱います。既定はページを開いた端末のタイムゾーンで、設定画面や共有用リンクで変えられます。 |
| カメラ別の時刻補正 | 時計がずれていたカメラの写真・動画だけを、一覧画面から「−7 時間」のように補正できます。補正はフォルダごとに保存され、共有用リンクにも含まれます。 |
| タイトルと日付のカード | 最初にタイトルと撮影期間を、日付が変わるところで「1日目 2025年7月12日（土）」のようなカードを表示します。時計が未設定のカメラの写真など、主な撮影期間から 30 日を超えて離れた日は「N日目」を付けずに日付だけを表示します。 |
| 写真 | フェード、ゆっくりズーム（ケン・バーンズ効果）、余白をぼかした写真で埋める表示。HEIC/HEIF は、ブラウザが表示できなければ同梱のライブラリで変換します。 |
| 動画 | Service Worker 経由でストリーミング再生します（全体をダウンロードせずに再生・シーク）。動画の前の写真やカードを表示している間に次の動画を読み込み始めておくので、切り替えるとすぐに再生が始まります（動画の再生中は、終わりの 10 秒前から次の動画を読み込みます）。終わったら次へ進み、最大再生時間も設定できます。ブラウザが再生できない形式（環境によっては HEVC）は Google ドライブのプレーヤーで再生します。 |
| サブフォルダ・ショートカット | 日ごとのサブフォルダやショートカットも読み込みます。開けないフォルダ（ショートカット先が削除された、権限がない）は飛ばして再生します。 |
| 自動更新 | 再生中も一定の間隔（既定は 5 分）でフォルダを確認し、追加・削除を反映します。一覧画面の「今すぐ更新」でも確認できます。 |
| 操作 | 再生/一時停止、前後、全画面、ミュート、一覧（日ごとのサムネイル）。キーボード、スワイプ、メディアキーに対応し、再生中は画面がスリープしないようにします。 |

**対応形式**

- 写真: JPEG、PNG、GIF、WebP、HEIC/HEIF、AVIF、BMP など。ブラウザで表示できない写真（TIFF、カメラの RAW（DNG、CR2 など）など）は、Google ドライブのサムネイルで表示します（RAW は大きな元ファイルをダウンロードせず、最初からサムネイルを使います）。SVG とアイコン（ICO）は表示しません。
- 動画: MP4、MOV、WebM など、ブラウザが再生できる形式。H.264 はほぼすべてのブラウザで再生できます。HEVC（iPhone の「高効率」設定）は Safari や Mac/Android の Chrome などで再生できます。

## 仕組みとプライバシー

- このアプリは静的なページだけでできていて、独自のサーバーはありません。ブラウザが接続するのは、アプリを置いたサイトと Google（ログイン、Google Drive API、サムネイル、ドライブのプレーヤー）だけです。ページの Content-Security-Policy で、それ以外への接続や外部スクリプトの読み込みを禁止しています。アクセス解析なども入っていません。
- 写真・動画はブラウザが Google ドライブから直接読み込みます。Google Drive API の応答はブラウザの HTTP キャッシュに残しません（サムネイルと、API キー方式で直接読み込む動画は通常のキャッシュの対象です）。
- ブラウザに保存するもの:
  - ログインのアクセストークン: タブごとの sessionStorage。約 1 時間で無効になり、タブを閉じると消えます。
  - 設定（フォルダ、接続設定、タイトル、時刻補正、表示の設定など）: localStorage。
  - 撮影日時の解析結果（ファイルの ID、撮影日時、時差、カメラの機種名）: localStorage。写真そのものやファイル名は保存しません。
- HEIC を表示できないブラウザでは、アプリに同梱した変換ライブラリ [heic-to](https://github.com/hoppergee/heic-to)（LGPL-3.0、`js/vendor/`）を、必要になったときだけ同じサイトから読み込みます。画像はブラウザの中で変換され、外部には送られません。
- Service Worker は、このアプリのページ内での写真・動画の読み込みだけを中継します。ログインの情報はタブごとに分けて扱い、このアプリの `sw.js` 以外の Service Worker には渡しません。

## 準備（Google Cloud）

Google ドライブへの接続方法は 2 種類あります。**フォルダを公開しなくて済む方法 1（ログイン）をおすすめします。**

| | 方法 1: Google アカウントでログイン | 方法 2: API キー（ログイン不要） |
| --- | --- | --- |
| フォルダの共有設定 | 制限付き（見る人のアカウントにだけ共有） | 「リンクを知っている全員」 |
| 見られる人 | フォルダを共有された人だけ | フォルダの URL を知っている人なら誰でも |
| 向いている使い方 | 写真を公開したくない場合 | テレビなどでの連続再生 |
| 注意 | ログインは約 1 時間で切れ、そのたびにボタンを押して延長します | フォルダの URL が漏れると、中身を誰でも見られます |

### 共通: Google Drive API を有効にする

1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作成します。
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を検索し、「有効にする」を押します。

### 方法 1: Google アカウントでログイン（OAuth）

1. 「Google Auth Platform」（「API とサービス」→「OAuth 同意画面」）を開き、アプリ名などを設定します。**対象（Audience）** は次のどちらかにします。
   - **自分のアカウントだけで見る場合**: 「Personal」。ログインできるのは、プロジェクトを作成したアカウントだけです。あとから「外部」などに変更することはできません。
   - **複数の Google アカウントで見る場合**: 「外部」にして、公開ステータスは「テスト」のままにし、見る人の Google アカウントを「テストユーザー」に追加します（最大 100 人）。ログインできるのはテストユーザーだけです。
     - ログイン時に、テスト中のアプリであることを知らせる警告（「Google はこのアプリを確認していません」など）が表示されます。表示されているアプリ名が自分で設定したものであることを確かめてから、「続行」で進めます（「続行」がない画面では「詳細」→「（アプリ名）（安全ではないページ）に移動」）。
     - Google の説明では、テストユーザーによる許可は 7 日で失効します。そのため、7 日ほどたつと再び許可を求められることがあります。
2. （任意）「データアクセス」で、スコープ `https://www.googleapis.com/auth/drive.readonly`（Google ドライブの読み取り専用）を追加します。追加しなくても、ログインのときにアプリがこのスコープを求めます。
3. 「クライアント」→「クライアントを作成」で、種類は **ウェブ アプリケーション** を選びます。
   - **承認済みの JavaScript 生成元** に、アプリを公開するオリジン（パスなし）を追加します。例: `https://<ユーザー名>.github.io`。ローカルで試すなら `http://localhost:8080` も追加します。
   - 「承認済みのリダイレクト URI」は不要です。クライアント シークレットも使いません（どこにも書かないでください）。
4. 表示された **クライアント ID**（`…apps.googleusercontent.com`）を、公開時のリポジトリ変数 `SLIDESHOW_CLIENT_ID`（[公開](#公開github-pages)を参照）に設定するか、アプリの「OAuth クライアント ID」欄に入力します。
5. Google ドライブで写真・動画のフォルダを右クリック →「共有」で、見る人の Google アカウントを閲覧者として追加します。「一般的なアクセス」は **「制限付き」** のままにします。

「スライドショーを開始」を押すと Google のログイン画面が開きます。**ログイン画面に表示されるアプリ名が、自分で設定したものであることを確かめてください。** 違う名前が表示されたら許可しないでください。Google ドライブのファイルの表示とダウンロードを求める画面で「許可」を押します（求める権限は 1 つだけなので、チェックボックスはありません）。

> ログインは Google の仕様で約 1 時間ごとに切れます。切れる 5 分前に「延長する」ボタンが表示され、切れた場合は再生が一時停止して「ログインして続ける」ボタンが表示されます（ブラウザのポップアップ制限のため、ボタンを押す操作が必要です）。ログインし直すと、止まったところから再生を続けます。

### 方法 2: API キー（ログイン不要）

> **注意:** この方法では、フォルダを「リンクを知っている全員」に共有する必要があります。フォルダの URL（または、フォルダを含む共有用リンク）を知った人は誰でも、ログインなしで中の写真・動画を見られます。また API キーはページの中で公開されます。写真を公開したくない場合は方法 1 を使ってください。

1. 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」を選びます。
2. 作成したキーを編集し、次のように制限します。
   - **アプリケーションの制限**: 「ウェブサイト」を選び、`https://<ユーザー名>.github.io/*` を追加します（ローカルで試すなら `http://localhost:8080/*` も）。ページは Google へのリクエストにオリジンだけをリファラーとして送るので、`/<リポジトリ名>/*` までの指定では拒否されます。
   - **API の制限**: 「キーを制限」で「Google Drive API」だけを選びます。
3. Google ドライブでフォルダを右クリック →「共有」→「一般的なアクセス」を **「リンクを知っている全員」（閲覧者）** にします。
4. API キーを、公開時のリポジトリ変数 `SLIDESHOW_API_KEY` に設定するか、アプリで「API キー（ログイン不要）」を選んで入力します。

> 2021 年以前に共有したフォルダでは、URL に `?resourcekey=...` が付いていることがあります。その場合は URL を丸ごと貼り付けてください。

## 公開（GitHub Pages）

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
2. **Settings → Secrets and variables → Actions → Variables** に、次のリポジトリ変数を設定します。公開するサイトの `config.js` は、デプロイのときにこれらの値から作られます（`scripts/write-config.mjs`）。一つも設定しなければ、リポジトリの `config.js`（空欄）がそのまま使われ、見る人が画面で入力します。**公開するサイトでは `SLIDESHOW_CLIENT_ID`（API キー方式なら `SLIDESHOW_API_KEY`）を設定して、接続設定を固定することをおすすめします。** 固定しないサイトでは、接続設定を何も保存していないブラウザでリンクを開くと、リンクに書かれた OAuth クライアント ID や API キーが警告なしで使われます（下記の[共有用リンク](#共有用リンク)）。ほかの変数は任意です。

   | 変数 | 内容 |
   | --- | --- |
   | `SLIDESHOW_CLIENT_ID` | OAuth クライアント ID（`…apps.googleusercontent.com`）。設定すると接続設定が固定されます（下記） |
   | `SLIDESHOW_API_KEY` | API キー（英数字・`-`・`_`）。設定すると接続設定が固定されます（下記） |
   | `SLIDESHOW_FOLDER` | 既定のフォルダの URL または ID |
   | `SLIDESHOW_TITLE` | 既定のタイトル（改行なし、120 文字以内。空欄ならフォルダ名） |
   | `SLIDESHOW_TIME_ZONE` | 既定の撮影地のタイムゾーン（IANA 名。例: `Asia/Tokyo`。空欄なら見る人の端末のタイムゾーン） |

   値の形式が正しくなければデプロイは失敗し、サイトは更新されません。
3. `main` ブランチに push すると（または Actions の「Deploy to GitHub Pages」を手動で実行すると）、`.github/workflows/pages.yml` が単体テストを実行してから `https://<ユーザー名>.github.io/<リポジトリ名>/` に公開します。変数を変えたときは、ワークフローを実行し直すと反映されます。
4. 公開したオリジン（`https://<ユーザー名>.github.io`）を、OAuth クライアントの「承認済みの JavaScript 生成元」や API キーの「ウェブサイト」の制限に追加します。

**接続設定の固定**: `SLIDESHOW_CLIENT_ID` か `SLIDESHOW_API_KEY`（つまり `config.js` の `clientId` / `apiKey`）を設定すると、接続設定はその値に固定されます。リンクの URL パラメータ、ブラウザに保存した値、画面の入力では変えられず、細工したリンクで別の OAuth クライアントや API キーを使わせることはできません。

- クライアント ID だけ: ログイン方式だけを使えます（API キー方式の選択肢と、クライアント ID・API キーの欄は表示されません）。
- API キーだけ: API キー方式だけを使えます（ログイン方式の選択肢と入力欄は表示されず、「このページに設定済みの API キーを使います。」と表示されます）。
- 両方: 接続方法は選べますが、値は設定したものに固定されます。

フォルダ・タイトル・タイムゾーンは既定値で、画面の入力や URL パラメータで変えられます。

**公開されるもの**: 公開したサイトと `config.js` は誰でも読めます。OAuth クライアント ID が公開されるのは通常のことですが、**「リンクを知っている全員」に共有したフォルダの URL は、リポジトリ変数にも `config.js` にも書かないでください**（誰でも写真を見られるようになります）。リポジトリも公開されるので、API キー・フォルダの URL・写真などをコミットしないでください（`.gitignore` で主な形式の写真・動画と、認証情報のファイルを除外しています）。

### 公開リポジトリのおすすめ設定

- **既定のブランチを保護する**: Settings → Rules → Rulesets →「New branch ruleset」で、対象に既定のブランチ（Include default branch）を選び、「Restrict deletions」「Block force pushes」「Require a pull request before merging」を有効にします。
- **デプロイを既定のブランチに限る**: Settings → Environments → `github-pages` の「Deployment branches and tags」が、既定のブランチだけになっていることを確かめます。
- **2 段階認証**: GitHub アカウントの 2 要素認証と、Google アカウント（Cloud プロジェクトの所有者と見る人）の 2 段階認証プロセスを有効にします。
- ワークフローのアクションはコミットの SHA で固定しています。更新するときは、Dependabot か手動で SHA を書き換えます。

## ローカルで試す

Node.js 18 以降があれば、依存パッケージなしで動きます。

```sh
npm start            # http://localhost:8080 で起動
```

ブラウザで `http://localhost:8080` を開きます（`127.0.0.1` は Google からは別のオリジンとして扱われるので、`localhost` で開いてください）。OAuth クライアントの「承認済みの JavaScript 生成元」に `http://localhost:8080`（API キーなら「ウェブサイト」の制限に `http://localhost:8080/*`）を追加しておきます。Service Worker と Google のログインは `https://` か `localhost` でしか動きません（`file://` で開くと動きません）。

## 使い方

### 設定画面

1. **写真・動画のフォルダ**: ドライブでフォルダを開いたときの URL（または ID）を貼り付けます。ログイン方式なら「フォルダを検索」で名前から選べます。
2. **ドライブへの接続方法**: 「Google アカウントでログイン」か「API キー（ログイン不要）」を選びます。公開時に接続設定を固定した場合は、使えない方法と固定した値の欄は表示されません。
3. **表示の設定（任意）**: 写真の表示時間（既定 6 秒）、動画の最大再生時間、切り替え効果、キャプション、撮影地のタイムゾーン、自動更新の間隔、写真の画質、タイトルなど。
4. **「スライドショーを開始」** を押すと、画面の設定をこのブラウザに保存して再生を始めます。

### 共有用リンク

設定画面の「共有用リンクをコピー」で、同じフォルダを同じ順番で再生できるリンクを作れます。リンクに含まれるのは次のものです。

- フォルダ（`folder`）、撮影地のタイムゾーン（`tz`。既定のタイムゾーンは開く人の端末によって違うので、常に含めます）、タイトル（`title`、設定したときだけ）
- そのフォルダのカメラ別の時刻補正（`fix=…`。最後の `fix=*` は「これがこのフォルダの補正のすべて」という印）
- 接続方法（`mode`）と、OAuth クライアント ID（`clientId`）または API キー（`key`）。ただし、公開時に固定した値はリンクに含めません（開いた人も同じ設定を使います）。接続方法が一つに決まっている場合は `mode` も含めません。

表示時間などの表示の設定は含みません。API キー方式のリンクを知った人は、誰でもそのフォルダを見られます。ログイン方式のリンクを開いた人は、それぞれ自分のアカウントでログインします（そのアカウントにフォルダが共有されていて、対象が「外部」ならテストユーザーに追加されている必要があります）。

リンクを開くと、リンクの値がブラウザに保存した値より優先されます。リンクの値が保存されるのは、その人が「スライドショーを開始」を押したときだけです（再生中のミュートの切り替えと「補正を適用」では、それぞれミュートの設定とそのフォルダの補正だけを保存します）。接続設定を固定していないサイトで、このブラウザに接続設定（OAuth クライアント ID か API キー）を保存してある場合、リンクの OAuth クライアント ID や API キーが保存した値と違うと（保存していない方式の値がリンクに含まれている場合も含みます）、「リンクで指定された接続設定です。信頼できるリンクでなければ使わないでください。」と表示し、自動では再生しません。「保存済みの接続設定に戻す」で元に戻せます。接続設定を何も保存していないブラウザでは比べるものがないため、警告なしでリンクの値を使います。公開するサイトでは接続設定を固定してください（[公開](#公開github-pages)）。

### 操作

| キー | 操作 |
| --- | --- |
| <kbd>Space</kbd> / <kbd>K</kbd> | 再生 / 一時停止 |
| <kbd>←</kbd> <kbd>→</kbd>（<kbd>PageUp</kbd> <kbd>PageDown</kbd>） | 前 / 次 |
| <kbd>Home</kbd> / <kbd>End</kbd> | 最初 / 最後 |
| <kbd>F</kbd> | 全画面 |
| <kbd>M</kbd> | ミュート |
| <kbd>G</kbd> | 一覧を開く / 閉じる（<kbd>Esc</kbd> でも閉じる） |

タッチ操作では、左右のスワイプで前後に移動し、タップで操作パネルを表示します。

### 撮影地のタイムゾーン

多くのカメラは、撮影日時を時差なしの現地時刻で記録します。このアプリはそれを「撮影地のタイムゾーン」の時刻として読み、UTC で記録される動画の日時などと正しく混ぜて並べます。既定は**ページを開いた端末のタイムゾーン**です。旅行先など、端末と違うタイムゾーンで撮った写真・動画を見るときは、設定画面の「撮影地のタイムゾーン」を撮影地のもの（IANA 名。例: `Asia/Tokyo`、`Europe/Paris`、`America/New_York`）にしてください。時差が記録されている写真・動画は、この設定の影響を受けません。

### カメラ別の時刻補正

カメラの時計がずれていた場合は、スライドショーの一覧画面（<kbd>G</kbd>）→「撮影時刻がずれている？ カメラごとに補正する」で、カメラごとに時間をずらせます。例えば、日本時間のままのカメラで、日本より 7 時間遅い撮影地（UTC+2）で撮った場合は **−7 時間** です。「補正を適用」を押すと、補正はフォルダごとにこのブラウザに保存され（ほかのフォルダには影響しません）、共有用リンクにも含まれます。

- 「〇〇（タイムゾーン記録あり）」のグループは、撮影地とは違う時差がファイルに記録されていた写真・動画です（時差を日本のままにしたカメラ、Pixel の `PXL_…` など）。時刻はすでに正しく解釈されているので、通常は補正の必要はありません。同じカメラでも時差の記録がない写真とは別のグループなので、補正が二重にかかることはありません。記録された時差が撮影地と同じ写真は、カメラ名のグループのままです。
- 「〇〇（動画）」のグループは、機種名の分かるカメラの動画のうち、動画ファイルの作成日時で並べているものです。カメラによってはここに現地時刻が記録されているため、写真とは別に補正できます。
- 機種名が読み取れない動画は、ファイル名から「GoPro（ファイル名から推定）」（`GOPR…`、`GX…` など）、「Canon（ファイル名から推定）」（`MVI_…`）、「DJI（ファイル名から推定）」（`DJI_…`）、「スマートフォン動画（ファイル名から推定）」（`PXL_…`、`VID_…`、`IMG_…`）に分けます。それ以外は「動画（機種不明）」、機種名の分からない写真は「写真（機種不明）」です。
- 「補正を適用」で変わるのは表に出ているグループの補正だけです。補正を保存してあっても今は該当する写真・動画がないグループは「今は該当する写真・動画がありません」と表示され、0 にすると取り消せます。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `folder` | フォルダの URL または ID |
| `mode` | `oauth`（ログイン）または `apikey`（`key` も可）。公開時に接続方法が一つに決まっている場合は無視します |
| `key`（`apiKey` も可） | API キー。`mode` がなければ API キー方式になります。公開時に接続設定を固定した場合は無視します |
| `clientId` | OAuth クライアント ID。公開時に接続設定を固定した場合は無視します |
| `tz` | 撮影地のタイムゾーン（IANA 名。例: `Asia/Tokyo`）。正しくない名前なら、エラーを表示して自動では再生しません |
| `title` | タイトル |
| `interval` | 写真の表示秒数（1〜120） |
| `refresh` | 自動更新の間隔（分、0〜1440。0 で自動更新しない） |
| `loop` | `0` で最後まで再生したら止まる、`1` で最初に戻る |
| `muted` | `1` で動画をミュート、`0` で音声あり |
| `fix` | カメラ別の時刻補正（`分:グループ名`、例: `fix=-420:Canon EOS R6`）。複数指定でき、`folder` のフォルダの補正として使います（`0` でその補正を取り消し）。`fix=*` があれば、リンクの `fix` がそのフォルダの補正のすべてになります（保存済みの補正に足さずに置き換え。`fix=*` だけなら補正なし） |
| `autostart=1` | 設定がそろっていれば、開いてすぐ再生します（下記） |

### 自動開始

`autostart=1` を付けたリンクは、設定がそろっていれば設定画面を飛ばしてすぐに再生します（テレビなどでの連続再生向け）。API キー方式ではそのまま始まり、ログイン方式ではこのタブでログイン済みの場合だけ始まります。`muted` を指定しなければ、ブラウザの自動再生の制限のため動画はミュートで始まります。`tz` が正しくない場合と、リンクの接続設定の警告が出た場合は自動では始まりません。

## セキュリティについて

- **公開されるもの**: サイト、`config.js`（OAuth クライアント ID、API キー、フォルダ、タイトル、タイムゾーン）、リポジトリ。写真・動画は Google ドライブに置き、公開されません（API キー方式では、フォルダの URL を知った人は見られます）。
- **ログインで許可する範囲**: `drive.readonly` は読み取り専用ですが、ログインした人の **Google ドライブ全体** を読める権限です。アクセストークンはこのアプリの中だけで使われ、Google 以外には送られませんが、心配な場合は、写真を見るためだけの Google アカウント（ほかのファイルを置いていないアカウント）にフォルダを共有し、そのアカウントでログインしてください。許可は Google アカウントの「リンク済みアプリ」（<https://myaccount.google.com/linkedapps>）→「Google アカウントへのアクセス権」からいつでも取り消せます。
- **同じオリジンにほかのサイトを置かない**: GitHub Pages では、同じアカウントのサイトはすべて同じオリジン `https://<ユーザー名>.github.io` で公開されます。同じオリジンのページ（とその Service Worker）は、このアプリのページを操作して、アクセストークンや保存した設定を読み取れます。このアプリを公開するアカウントでは、ほかの GitHub Pages サイト（別リポジトリのサイトや `<ユーザー名>.github.io` リポジトリ）を公開しないでください。ほかのサイトも公開したい場合は、このアプリ専用の GitHub アカウントを使うか、このリポジトリに専用のカスタムドメイン（サブドメイン）を設定してください。
- **共有の端末**: 家族の共用の端末などでは、ゲストモードかシークレットウィンドウを使ってください。見終わったら設定画面の「ログアウト」を押します。ログアウトはトークンを取り消して消し、撮影日時の解析結果と読み込んだ写真も消します（保存した設定は残ります）。「ログアウト」は、ログインの有効期限が切れたあとやページを開き直したあとでも、トークンか撮影日時の解析結果がこのブラウザに残っていれば表示されます。ブラウザでの Google アカウントのログインは残るので、Google からもログアウトしてください。
- **フォルダの共有設定**: ログイン方式では、フォルダの「一般的なアクセス」を「制限付き」のままにし、見る人のアカウントにだけ共有してください。
- **ほかのホストを追加するとき**: `index.html` の Content-Security-Policy（`<meta>`）で接続先を Google に限っています。ほかのホスト（別の API、CDN など）を使うように変更する場合は、この meta も書き換えてください。GitHub Pages ではヘッダーを付けられないため、ほかのサイトの枠（iframe）に埋め込まれることは防げません。

## 並び順の決め方

1 件ごとに次の順で撮影日時を決め、早い順に並べます（同時刻はファイル名順）。

1. **写真**: ファイル先頭の EXIF から直接読み取った撮影日時（`DateTimeOriginal`）。`OffsetTimeOriginal`（時差）があればそれで、なければ撮影地のタイムゾーンで解釈します（再生しながら裏で読み取り、結果はブラウザに保存します）。
2. **写真**: Google ドライブが読み取った撮影日時（撮影地のタイムゾーンで解釈）。
3. **動画**: 動画ファイル内の iPhone の撮影日時（`com.apple.quicktime.creationdate`、時差付き）→ `©day` → MP4 の作成日時（`mvhd`、UTC）。必要な部分だけを Range リクエストで読み取ります。
4. **ファイル名**: `IMG_20250712_143000`、`VID_…`、`20250712_143000`、`Screenshot_…`、`2025-07-12 14.30.00` など（撮影地の現地時刻）。Google Pixel の `PXL_…` は UTC として扱います。WhatsApp の `IMG-20250712-WA0001` は日付だけ（その日の正午）です。
5. **ドライブ上の日時**: 更新日時と作成日時の早い方（一覧に「推定」と表示）。スマートフォンのドライブアプリからアップロードした場合などはアップロードした時刻になるため、正確ではありません。

## うまくいかないとき

**順番がずれる**

- **カメラの時計がずれていた**: 「[カメラ別の時刻補正](#カメラ別の時刻補正)」で補正します。
- **撮影地と違うタイムゾーンで表示されている**: 設定画面の「撮影地のタイムゾーン」を撮影地のものにします（時差情報付きの写真・動画は影響を受けません）。
- **メッセージアプリなどで送られてきた写真**: 撮影日時が消えていることがあります。ファイル名に日時がなければ、ドライブ上の日時（推定）になります。

**接続・ログイン**

- **「Google はこのアプリを確認していません」と表示される**: 「テスト」のアプリでは表示されます。アプリ名が自分で設定したものなら「続行」（または「詳細」→「…に移動」）で進めます。
- **ログインできない（アクセスがブロックされる）**: 対象が「外部」ならそのアカウントがテストユーザーに追加されているか、「Personal」ならプロジェクトを作成したアカウントでログインしているかを確認します。あわせて、「承認済みの JavaScript 生成元」にページのオリジン（`https://<ユーザー名>.github.io`、パスなし）が登録されているかも確認します。
- **ログイン用のポップアップが開かない**: ブラウザでこのサイトのポップアップを許可します。
- **「ファイルまたはフォルダが見つかりません」**: ログイン方式ではそのアカウントにフォルダが共有されているか、API キー方式ではフォルダが「リンクを知っている全員」に共有されているかを確認します。`?resourcekey=` 付きの URL は丸ごと貼り付けます。
- **「API キーのウェブサイト制限（HTTP リファラー）により拒否されました」**: API キーの「ウェブサイト」の制限に `https://<ユーザー名>.github.io/*` があるかを確認します。
- **「Google Drive API が有効になっていません」**: Cloud プロジェクトで Google Drive API を有効にします。
- **公開した設定が反映されない**: リポジトリ変数を変えたあとは、Actions でワークフローを実行し直します。

**再生**

- **動画が再生できない**: ブラウザが対応していない形式（HEVC など）は、API キー方式では Google ドライブのプレーヤーで自動再生し、ログイン方式では「Google ドライブのプレーヤーで再生」ボタンを表示します。
- **動画の音が出ない**: ブラウザの自動再生の制限で音が止まっているときは、画面をクリック・タップするかキーを押すと音が出ます。ミュートになっているとき（自動開始したときなど）は、<kbd>M</kbd> かミュートボタンで解除します。

## 開発・テスト

```sh
npm test                 # 単体テスト（Node.js の標準テストランナー。Node.js 22 以降）
npm run fixtures         # E2E テスト用の素材を生成（Python 3 + Pillow + pillow-heif + ffmpeg）
npm run test:e2e         # 疑似 Google Drive API とヘッドレス Chromium による E2E テスト（Playwright が必要）
```

E2E テストは本物の Google のサービスには接続しません。疑似 Google Drive API サーバー、テスト素材、各テストの内容は [tests/README.md](tests/README.md) を参照してください。
