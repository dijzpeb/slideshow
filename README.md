# 旅の写真スライドショー

Google ドライブのフォルダに写真や動画を入れておくと、**撮影した順に並べてスライドショーで再生する**ウェブアプリです。
フィンランド旅行のように、複数のスマホやカメラで撮った写真・動画が混ざっていても、撮影日時を読み取って時系列に並べます。

- サーバー不要の静的サイト（HTML / CSS / JavaScript のみ）。GitHub Pages などにそのまま置けます。
- 写真・動画はブラウザと Google ドライブの間で直接やり取りされ、ほかのサーバーには送られません。
- 再生中にフォルダへ写真を追加すると、自動更新で撮影日時の位置に入ります（既定は 5 分ごと）。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 時系列の並び替え | 写真は EXIF の撮影日時（時差情報があればそれも使用）、動画はファイル内のメタデータ（iPhone の撮影日時、MP4 の作成日時）から並べます。見つからなければファイル名（`IMG_20250712_143000.jpg`、`PXL_…` など）、最後の手段としてドライブ上の日時を使います。 |
| 撮影地のタイムゾーン | 既定は `Europe/Helsinki`（フィンランド）。EXIF の時刻を現地時刻として扱うので、写真（現地時刻）と動画（UTC）が正しく混ざります。 |
| カメラ別の時刻補正 | カメラの時計を日本時間のままにしていた場合も、一覧画面でそのカメラだけ「−6 時間」などと補正できます。補正はフォルダごとに保存され、共有用リンクにも含まれます。 |
| 日付の区切り | 「1日目 2025年7月12日（土）」のようなカードを日ごとに表示。最初にタイトルと旅の期間も表示します。時計が未設定のカメラの写真など、旅行の期間から大きく（30 日を超えて）離れた日は「N日目」を付けずに日付だけを表示します。 |
| 写真 | フェード、ゆっくりズーム（ケン・バーンズ効果）、余白をぼかした写真で埋める表示。HEIC（iPhone）も表示できます（Safari 以外は自動変換）。 |
| 動画 | Service Worker 経由でストリーミング再生（全体をダウンロードせずにすぐ再生）。終わったら次へ進みます。最大再生時間も設定できます。ブラウザが対応していない形式（例: Windows の Chrome で再生できない HEVC）は、Google ドライブのプレーヤーで表示します。 |
| 操作 | 再生/一時停止、前後、全画面、ミュート、一覧（日ごとのサムネイル）。キーボード・スワイプにも対応。再生中は画面がスリープしないようにします。 |
| サブフォルダ | 「Day1」「Day2」などのサブフォルダやショートカットも読み込みます。開けないフォルダ（ショートカット先が削除された・権限がない）は飛ばして再生します。 |

キーボード操作: <kbd>Space</kbd> 再生/一時停止、<kbd>←</kbd> <kbd>→</kbd> 前/次、<kbd>F</kbd> 全画面、<kbd>M</kbd> ミュート、<kbd>G</kbd> 一覧、<kbd>Home</kbd> / <kbd>End</kbd> 最初/最後

## 使い方（概要）

1. Google ドライブにフォルダを作り（例: 「フィンランド旅行 2025」）、写真・動画を入れます。日ごとのサブフォルダに分けても構いません。
2. 下の「準備」の手順で、Google Cloud の **API キー** または **OAuth クライアント ID** を用意します（最初の 1 回だけ）。
3. アプリを開き、フォルダの URL と API キー（または OAuth クライアント ID）を入力して「スライドショーを開始」を押します。

## 準備：Google Cloud の設定

接続方法は 2 種類あります。用途に合わせて選んでください。

| | A. API キー（ログイン不要） | B. Google アカウントでログイン |
| --- | --- | --- |
| フォルダの共有設定 | 「リンクを知っている全員」が閲覧可 | 非公開のままで OK |
| 見る人 | URL を知っている人なら誰でも（ログイン不要） | 自分（とアクセス権のある人） |
| 向いている使い方 | テレビや家族の端末で連続再生 | 自分だけで見る、写真を公開したくない |
| 注意 | フォルダの URL を知られると中身を見られます | ログインは約 1 時間で切れ、その都度ボタンを押して延長します |

### 共通: Google Drive API を有効にする

1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作成します（例: `trip-slideshow`）。
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を検索し、「有効にする」を押します。

### A. API キーを使う場合

1. 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」。
2. 作成したキーを編集し、次のように制限します（キーはページ内で公開されるため、制限を強くおすすめします）。
   - **アプリケーションの制限**: 「ウェブサイト」を選び、アプリの URL を追加（例: `https://<ユーザー名>.github.io/*`、ローカルで試すなら `http://localhost:8080/*`）。
   - **API の制限**: 「キーを制限」→「Google Drive API」のみ。
3. Google ドライブでフォルダを右クリック →「共有」→「一般的なアクセス」を **「リンクを知っている全員」（閲覧者）** にします。
4. アプリで「API キー（ログイン不要）」を選び、API キーとフォルダの URL を入力します。

> 2021 年以前に共有したフォルダでは、URL に `?resourcekey=...` が付いていることがあります。その場合は URL を丸ごと貼り付けてください（自動で処理します）。

### B. Google アカウントでログインする場合

1. 「Google Auth Platform」（「API とサービス」→「OAuth 同意画面」）を開いて設定します。
   - **自分だけで使う場合（おすすめ）**: 「Personal（個人）」モードで作成すると、「確認されていないアプリ」の警告や 7 日ごとの再同意がなくなります。ただし、ログインできるのはプロジェクトを作成したアカウントだけです。
   - **家族など複数の Google アカウントで使う場合**: ユーザーの種類を「外部」にし、公開ステータスは「テスト」のままで、使う人の Gmail アドレスを「テストユーザー」に追加します（最大 100 人）。ログイン時に「Google はこのアプリを確認していません」と表示されたら「詳細」→「（安全ではないページ）に移動」で進めます。テスト中のアプリは 7 日ごとに再同意が必要です。
   - 「データアクセス」でスコープ `https://www.googleapis.com/auth/drive.readonly`（Google ドライブのファイルの表示）を追加します。
2. 「クライアント」→「クライアントを作成」→ 種類は **ウェブアプリケーション**。
   - **承認済みの JavaScript 生成元**に、アプリを公開する URL のオリジンを追加（例: `https://<ユーザー名>.github.io`、ローカルなら `http://localhost:8080`）。
3. 表示された **クライアント ID**（`…apps.googleusercontent.com`）をアプリの「OAuth クライアント ID」欄に入力します。
4. 「スライドショーを開始」を押すと Google のログイン画面が開きます。「Google ドライブのファイルの表示」を許可してください。

> ログインは Google の仕様で約 1 時間ごとに切れます。切れる 5 分前に「延長する」ボタンが表示され（開始した時点で残りが 5 分を切っていれば開始してすぐ）、切れた場合は再生が一時停止して「ログインして続ける」ボタンが表示されます（ブラウザのポップアップ制限のため、ボタンを押す操作が必要です）。「延長する」のログインが期限切れのあとに終わった場合も、そのまま続きから再生します。長時間の連続再生には A の API キー方式が向いています。

## 公開する（GitHub Pages）

1. このリポジトリを GitHub に置きます（このリポジトリ自体でも OK）。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` ブランチに push すると、`.github/workflows/pages.yml` がテストを実行してから `https://<ユーザー名>.github.io/<リポジトリ名>/` に公開します。
4. 公開した URL を、API キーの「ウェブサイト制限」や OAuth クライアントの「承認済みの JavaScript 生成元」に追加します。

`config.js` に API キー・クライアント ID・フォルダを書いておくと、ページを開いた人は入力なしで使えます。

```js
window.SLIDESHOW_CONFIG = {
  clientId: '',               // OAuth クライアント ID
  apiKey: 'AIza...',          // API キー
  folder: 'https://drive.google.com/drive/folders/xxxxxxxx',
  title: 'フィンランド旅行 2025',
  timeZone: 'Europe/Helsinki',
};
```

設定画面の「共有用リンクをコピー」で、設定を含んだ URL（`?folder=…&key=…`）も作れます。そのフォルダのカメラ別の時刻補正もリンクに含まれるので、開いた人も同じ順番で再生できます（開いた人のブラウザに以前のリンクなどで保存されていた、そのフォルダの補正はリンクの内容に置き換わります）。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `folder` | フォルダの URL または ID |
| `mode` | `apikey` または `oauth` |
| `key` | API キー（指定すると API キー方式） |
| `clientId` | OAuth クライアント ID |
| `tz` | 撮影地のタイムゾーン（例: `Europe/Helsinki`） |
| `interval` | 写真の表示秒数 |
| `title` | タイトル |
| `refresh` | 自動更新の間隔（分、0 で無効） |
| `fix` | カメラ別の時刻補正（`分:グループ名`、例: `fix=-360:Canon EOS R6`）。複数指定でき、`folder` のフォルダの補正として使います（`0` でその補正を取り消し）。`fix=*` があれば、リンクの `fix` がそのフォルダの補正のすべてです（保存済みの補正に足すのではなく置き換え。`fix` が `*` だけなら補正なし）。共有用リンクには常に付きます |
| `autostart=1` | 設定がそろっていれば、開いてすぐ再生（テレビ向け。音声付き自動再生の制限のため動画はミュート） |

## ローカルで試す

Node.js 18 以降があれば、依存パッケージなしで動きます。

```sh
npm start            # http://localhost:8080 で起動
```

Service Worker と Google ログインは `https://` か `localhost` でしか動きません（`file://` で開くと動きません）。

## 並び順の決め方

1 枚ごとに次の順で撮影日時を決め、早い順に並べます（同時刻はファイル名順）。

1. **写真**: ファイル先頭の EXIF を直接読み取った撮影日時（`DateTimeOriginal`）。`OffsetTimeOriginal`（時差）があればそれで、なければ撮影地のタイムゾーンで解釈します（再生しながら裏で読み取り、結果はブラウザに保存されます）。
2. **写真**: Google ドライブが読み取った撮影日時（撮影地のタイムゾーンで解釈）。
3. **動画**: 動画ファイル内の iPhone の撮影日時（`com.apple.quicktime.creationdate`、時差付き）→ `©day` → MP4 の作成日時（`mvhd`、UTC）。必要な部分だけを Range リクエストで読み取ります。
4. **ファイル名**: `IMG_20250712_143000`、`VID_…`、`20250712_143000`、`Screenshot_…`、`2025-07-12 14.30.00` など（現地時刻）。Google Pixel の `PXL_…` は UTC として扱います。
5. **ドライブ上の日時**: 更新日時と作成日時の早い方（一覧に「推定」と表示）。スマホのドライブアプリからアップロードした場合はアップロード時刻になるため、正確ではありません。

### 順番がずれるときは

- **カメラの時計がずれていた**: スライドショーの一覧画面（<kbd>G</kbd>）→「撮影時刻がずれている？」で、カメラごとに時間をずらせます。日本時間のままだったカメラをフィンランドの夏時間（UTC+3）に合わせるには **−6 時間**、冬時間（UTC+2）なら **−7 時間** です。補正はフォルダごとにこのブラウザに保存され（ほかのフォルダには影響しません）、共有用リンクにも含まれます。
  - 「〇〇（タイムゾーン記録あり）」のグループは、撮影地とは違う時差（UTC からのずれ）がファイルに記録されていた写真・動画です（時差を日本のままにしたカメラ、Pixel の `PXL_…` など）。時刻はすでに正しく解釈されているため、通常は補正の必要はありません。同じカメラでも時差の記録がない写真とは別のグループになるので、片方の補正がもう片方に二重にかかることはありません。記録された時差が撮影地と同じ写真は、カメラ名のグループのままです（時計の数分のずれなどの補正がそのまま効きます）。
  - 「〇〇（動画）」のグループは、機種名の分かるカメラの動画のうち、動画ファイルの作成日時で並べているものです。カメラによってはここに現地時刻が記録されているため、写真とは別に補正できます。
  - 機種名が読み取れない動画は、ファイル名から「GoPro（ファイル名から推定）」（`GOPR…`、`GX…`）、「Canon（ファイル名から推定）」（`MVI_…`）、「DJI（ファイル名から推定）」（`DJI_…`）、「スマートフォン動画（ファイル名から推定）」（`PXL_…`、`VID_…`、`IMG_…`）に分けます。それ以外は「動画（機種不明）」です。
  - 「適用」で変わるのは表に出ているグループの補正だけです。補正を保存してあっても今は該当する写真・動画がないグループ（裏で写真の撮影日時を読み終えると「タイムゾーン記録あり」に移る写真など）は「今は該当する写真・動画がありません」と表示され、0 にすると取り消せます。
  - 以前の版で保存した補正（フォルダ別になる前のもの）は、そのとき開いていたフォルダの補正として引き継ぎます。グループの分け方が変わったファイル（以前は「動画（機種不明）」だった Canon・Android の動画や、ファイル名で分けるようになった動画など）にも、以前と同じ補正がかかります。
- **フィンランド以外で撮った写真が混ざる**: 表示の設定の「撮影地のタイムゾーン」を変えてください（時差情報付きの写真・動画は影響を受けません）。
- **LINE などで送られてきた写真**: 撮影日時が消えていることがあります。ファイル名に日時がなければドライブ上の日時（推定）になります。

## 対応形式

- 写真: JPEG、PNG、WebP、GIF、AVIF、HEIC/HEIF（ブラウザで表示できない形式は Google のサムネイルで表示を試みます）
- 動画: MP4、MOV（H.264 はほぼすべてのブラウザで再生可）、WebM。HEVC（iPhone の「高効率」設定）は Safari・Mac/Android の Chrome などで再生できます。再生できない場合、API キー方式では Google ドライブのプレーヤーで自動再生し、ログイン方式では「ドライブのプレーヤーで再生」ボタンを表示します。

## プライバシーとセキュリティ

- このアプリは静的なページで、独自のサーバーはありません。写真・動画はブラウザが Google ドライブから直接取得します。
- ログインのアクセストークンは、ブラウザのタブ内（sessionStorage）にだけ保存され、約 1 時間で無効になります。読み取り専用の権限（`drive.readonly`）のみを要求します。
- 設定と、撮影日時の解析結果（写真・動画の ID と日時のみ）はブラウザの localStorage に保存されます。
- HEIC を表示できないブラウザでは、アプリに同梱した変換ライブラリ [heic-to](https://github.com/hoppergee/heic-to)（LGPL-3.0、`js/vendor/`）を、必要になったときだけこのアプリと同じサイトから読み込みます。外部の CDN からスクリプトを読み込むことはありません。画像はブラウザ内で変換され、外部には送られません。
- Service Worker が中継するのは、このアプリのページ内での写真・動画の読み込みだけです。ほかのサイトから直接開かれた URL（ページの移動や iframe）には応答せず、写真・動画以外の種類のファイルはページとして表示できない形式で返します。認証情報はタブごとに分けて扱います。

## 開発

```sh
npm test                 # 単体テスト（Node.js の標準テストランナー）
npm run fixtures         # E2E 用のテスト素材を生成（Python 3 + Pillow + pillow-heif + ffmpeg が必要）
npm run test:e2e         # 疑似 Google Drive API とヘッドレス Chromium によるエンドツーエンドテスト（Playwright が必要）
```

テスト用の疑似 Google Drive API サーバーやテスト素材の詳細は [tests/README.md](tests/README.md) を参照してください。

